## Ch6 问答：root inode 的作用

root inode 是 easy-fs 目录树的入口，也是本实验扁平文件系统中所有文件名到 inode 编号映射的目录。挂载文件系统后，内核先获得 root inode，再通过它的目录项完成 `find`、`create`、`link`、`unlink` 和目录枚举；普通文件 inode 即使内容完好，如果失去 root 目录项，也无法再通过路径找到。

root inode 的数据损坏可能造成以下后果：

- 目录项名称或 inode 编号损坏后，文件会消失、指向错误文件，或出现多个名称异常共享同一 inode。
- root inode 的大小损坏会导致目录遍历遗漏条目或越界读取无效目录项。
- root inode 的直接/间接数据块指针损坏会让整个目录不可读，严重时可能把普通数据解释成目录项。
- 错误的 inode 编号可能使后续写入、截断或 unlink 回收仍在使用的数据块，扩大文件系统损坏范围。

因此 root inode 属于文件系统的关键元数据。可靠文件系统通常需要一致性检查、日志或写时复制、元数据校验和及备份等机制；当前 easy-fs 没有这些保护，root inode 损坏后通常需要离线修复或重建文件系统。

## Ch7 问答

### 1. pipe 的实际应用

Linux shell 中常用管道把前一个程序的标准输出连接到后一个程序的标准输入。例如统计文件行数：

```sh
cat example.txt | wc -l
```

shell 创建管道并 fork 两个子进程：`cat` 把文件内容写入管道写端，`wc -l` 从读端持续读取并统计换行符。父进程关闭自己不使用的两端并等待子进程结束。类似地，`ps aux | grep qemu`、编译器各阶段的流式处理也可使用管道组合独立程序。

### 2. 更易用的多进程通信机制

可以在内核中实现“命名邮箱/消息队列”机制，而不是让每一对进程单独建立管道：

1. 进程用一个字符串名称或整数 key 创建/打开邮箱，内核返回描述符。
2. 任意多个进程只要拥有权限，就能向同一邮箱发送带类型和长度的消息，也能阻塞或非阻塞地接收。
3. 内核为邮箱维护有界消息队列、等待发送者/接收者队列和引用计数；队列满或空时按调用参数阻塞、返回或设置超时。
4. 权限可以按创建者、用户组或显式能力令牌控制；进程退出时只释放自己的句柄，最后一个引用关闭后再销毁匿名邮箱。
5. 若要实现请求—响应，可在消息头携带发送者 PID、关联 ID 和回复邮箱，不需要预先为每对进程创建双向管道。

这种设计把通信关系从完全图中的大量点对点管道，简化为围绕服务名或主题的共享通道；还可以进一步扩展为发布—订阅，让发送者无需知道所有接收者。
